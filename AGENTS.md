# Project rules for all agents

These rules apply to every agent and every session working in this repository. The Next.js block above is managed by
`next dev`; keep these rules below it and never edit inside the markers.

## 1. Structure: where things live

| Folder | Holds | Notes |
|---|---|---|
| `app/` | `layout.tsx`, `page.tsx`, `globals.css`, `styles/*.css` | Routing files only. `globals.css` only `@import`s; the cascade order is deliberate. |
| `components/site/` | page-wide chrome (Header, Preloader) | |
| `components/story/` | the ten-chapter scroll story | `.tsx` for React, `kebab-case.ts` for the imperative GSAP/Lenis/canvas modules it drives. |
| `components/products/` | Product Range, splash, home scenes, enquiry ending | Area hooks in `components/products/hooks/`; area CSS sits beside the components. |
| `data/` | every word and the product list | Content only: plain typed objects, no logic, no media lookups. |
| `lib/` | framework-free helpers (math, viewport, events, device, scroll) | |
| `lib/media/`, `lib/story/`, `lib/product/` | domain logic: frame packs and caching, story timeline and hero loop, product data and pacing | Adds numbering/media to `data/`; no JSX. |
| `hooks/` | hooks shared by more than one area | An area-only hook goes in that area's `hooks/`. |
| `public/` | runtime media (`frames/`, `films/`, `stills/`, `images/`), manifests, `_headers` | Generated by `scripts/`; do not hand-edit manifests. |
| `scripts/`, `tests/`, `docs/` | media tooling, `node:test` suites, project notes | Git-ignored, local only. |
| `tmp/`, `output/` | throwaway captures and QA output | Git-ignored. Never referenced by app code. |

- Do not create a new top-level folder, a new `components/<area>/`, or a new `lib/<domain>/` without asking the user.
- Put new code in the folder its responsibility belongs to, even if a file elsewhere is more convenient to edit.
- Dependency direction: `app` → `components` → `hooks` / `lib` → `data`. `lib/` and `data/` never import from
  `components/` or `app/`; `data/` imports nothing but types.
- When files are added, moved or removed, update the folder tree in `README.md` in the same change.

## 2. Creating files

- Prefer editing an existing file. Create a new one only for a distinct responsibility (a new component, hook, or
  domain module), not to hold a few lines that fit an existing file.
- Naming:
  - React components: `PascalCase.tsx`, one exported component per file (small private sub-components may stay).
  - Hooks: `useCamelCase.ts`.
  - Other modules and CSS: `kebab-case.ts` / `kebab-case.css`.
  - Tests: `tests/<module-name>.test.ts`, using `node:test` and `node:assert` (run by `npm test` via tsx).
  - Scripts: `scripts/kebab-case.py` or `.ts`.
- New global CSS goes in `app/styles/<name>.css` and must be added to `app/globals.css` at the right cascade position.
  Area CSS (`components/<area>/<name>.css`) is imported by the component that owns it.
- No new Markdown files outside `docs/` (and this file / `README.md`) unless the user asks.
- Never leave scratch files in the repo root or source folders. Temporary scripts, screenshots and logs go to the
  session scratchpad, or `tmp/` if the user should keep them.
- Do not add npm dependencies, config files (`*.config.*`, `vercel.json`, `tsconfig.json`) or new build steps without
  asking. Pin exact versions for runtime dependencies, as `package.json` already does.
- Generated media goes in `public/` only through the scripts in `scripts/`, which also refresh the manifests.

## 3. Writing code

**Language and style**
- Strict TypeScript. No `any`, no `@ts-ignore`; narrow types instead. Use `type` aliases for props and data shapes.
- Double quotes, semicolons, two-space indent; match the formatting of the file being edited.
- Imports: `@/…` across folders, relative (`./`, `../`) within the same folder tree. Type-only imports use `import type`.
- Named exports everywhere. Default exports only where Next.js requires them (`app/layout.tsx`, `app/page.tsx`).
- `"use client"` only on components that use state, effects, refs or browser APIs; keep `lib/` and `data/` free of it.
- Name magic numbers as `SCREAMING_SNAKE_CASE` constants at the top of the module, with a comment giving the unit.
- Keep files focused: when a file passes ~250 lines or holds two responsibilities, split it along the folder rules above.

**Comments**
- A one-line `/** … */` above every exported function, component, type and constant, saying what it is for.
- Inline comments explain *why* (a browser quirk, a pacing choice, a measured number), not what the code does.
- British spelling in comments and copy (colour, neighbour, behaviour), matching the existing code.

**Content and data**
- Never hard-code user-facing words in components. Text belongs in `data/*.ts`; media paths and numbering are added
  in `lib/story/scene-data.ts` or `lib/product/product-data.ts`.

**CSS**
- Tailwind v4 is available, but the site is styled with hand-written CSS; follow the file you are in.
- Class names carry their area prefix: `pr-` (product range), `home-`, `enquiry-`/`ending-`, `scene-`/`story-`,
  `menu-`, `preloader-`, `nav-`. Pass per-element values through CSS custom properties (`--pr-offset`).
- Never write `backdrop-filter` together with `-webkit-backdrop-filter`: the build drops both.
- Inline-style custom properties beat media-query resets; reset them in the component, not only in phone CSS.

**Motion and media**
- Every animated feature needs a reduced-motion path (see `hooks/useMotionPreference.ts`, `components/story/reduced-story.ts`).
- Scroll films are frame packs drawn on a canvas (`lib/media/film-cache.ts`, `lib/media/frame-painter.ts`).
  Never scrub a `<video>` with the scroll.
- Clean up everything you start: GSAP timelines/ScrollTriggers, Lenis, listeners, observers and animation frames are
  released in the effect cleanup.
- Use `<img>` with explicit `srcSet`/`sizes` (the site is a static export; `next/image` optimisation is not available),
  with the eslint disable comment the existing components use.

## 4. Before finishing a change

1. `npm run lint`, `npm run typecheck` and `npm test` all pass; add or update a test in `tests/` when changing logic in `lib/`.
2. Visible changes are checked in the browser on the dev server (`npm run dev`, always port 8000), at desktop and
   phone widths and with reduced motion on.
3. `README.md` and the relevant `docs/` note are updated if structure, commands or the media pipeline changed.
4. No stray files: `git status` shows only the files the change intended.
5. Do not commit, push or delete files unless the user asks.
